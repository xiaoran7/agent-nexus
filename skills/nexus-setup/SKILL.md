# Agent-Nexus 零负担协同防护自检与接入指南 (nexus-setup)

本指南遵循最高原则：**Agent-Nexus 绝不能给目标项目产生任何一点负担。**
业务项目不需要新增任何文件，不需要修改 `.gitignore`，更不需要在 `AGENTS.md` 里塞满复杂的规矩说明。

Nexus 的定位就像道路上的红绿灯和交警系统，是建在操作系统/开发机全局的，车（AI 助手）开进任何道路（项目）都自然受到保护，而不是要求每条路上都立牌子写交规。

---

## 0. 第零步：3 秒快速判定（已装全局则立即收工！）

**任何 AI 助手在执行本技能时，必须优先执行这第一道检查，严禁盲目往业务项目里写配置：**

1. **查验本机全局设置**：
   检查用户的全局配置文件（如 `~/.claude/settings.json`）中的 `hooks.PreToolUse` 是否已包含 `nexus-hook.mjs`。
2. **判定结论**：
   - **如果已经包含（开发机绝大多数情况）**：
     **说明本机早已全局就绪！当前项目（以及全机所有工程）已经处于全自动防撞车、大文件锚点锁与提交秒级释放的静默保护之中。**
     **AI 必须立即向用户汇报：“本机全局已安装 Nexus 防护钩子，当前项目已自动受保护，无需做任何改动或新增任何文件，直接开工即可！”，然后立即结束本技能流程，严禁在目标项目创建 `.mcp.json` 或修改 `.gitignore`！**
   - **如果尚未包含（纯全新开发机首次初始化）**：
     仅在此种情况下，才继续执行下述的全局一次性安装（全局配一次，全机一劳永逸）。

---

## 1. 全新机器首次初始化（全局一次性配置，全机受益）

如果上一步检查发现全局配置尚未包含钩子，仅需在全局执行一次安装，**依然对所有业务项目 0 改动**：

### 第一步：确保 Nexus 后台服务在运行
在 Agent-Nexus 本地根目录下运行：
```bash
# 启动后台守护服务（默认监听 4300 端口）
node src/cli.js start
```
服务启动后，打开浏览器 `http://127.0.0.1:4300/` 即可看到中文协同大屏。

### 第二步：安装全局防护钩子（全机仅需执行一次）
```bash
# 注册全局 PreToolUse 钩子到用户的 ~/.claude/settings.json
node "<Agent-Nexus路径>/src/cli.js" hook:install
```

### 第三步：直接开工！
安装完后，全机所有项目（包括已有项目和后续新建的项目）立刻全自动受保护，**目标项目不需要动任何一个文件**。

---

## 2. 核心工作原理（全自动静默运行，无需手动干预）

1. **自动防撞车与排队**：
   当助手 A 正在改某个文件时，助手 B 如果也去改这个文件，底层的全局 Hook 会自动挡下 B，并告知对方是谁、预计等待多久。
2. **大文件局部锁（聪明放行）**：
   如果是几千行的大型文件且改动位于不同区域（例如页面头部 vs 底部数据流），系统自动放行，互不干扰。
3. **提交自动解锁（零感释放）**：
   助手改完一旦执行 `git commit` 或 `git push`，系统秒级自动解开文件锁并叫醒后面排队的助手，不需要任何人手动点释放。
4. **跨工作树（Git Worktree）自动识别**：
   哪怕会话开在不同的工作树分支上，系统会自动认出它们是同一个项目，杜绝跨分支撞车。

## 3. 可选进阶场景说明（非必须）

如果用户特别要求在 Claude 对话里手动使用 MCP 工具（比如跨会话对讲 `nexus_dialogue_send`，或查看长期备忘录 `nexus_search_memory`）：
- **推荐做法**：把 Nexus MCP 同样注册在用户的全局 MCP 配置中，保持各个业务项目依然 0 文件。
- **避免做法**：尽量不要在业务项目根目录下新建 `.mcp.json`，防止污染 Git 仓库状态。

## 4. 常见问题大白话速查

| 问 | 答 |
|---|---|
| **我新开了一个项目，需要运行 nexus-setup 吗？** | **完全不用！** 本机已有全局 Hook，任何项目里的会话都会被自动保护，零配置开工。 |
| **为什么修改文件时被拦住了？** | 说明另一个会话正在改同一个文件。命令行里会显示对方名字和预估等待时间；等对方 `git commit` 或做完后，你就会被自动唤醒。 |
| **改大文件的不同地方也会被拦吗？** | 不会！Nexus 支持锚点区域锁，改不同模块互不干扰，安全并发。 |
| **我和同事拉取代码会看到 Nexus 的垃圾文件吗？** | 完全不会！零文件入库原则保证了远端仓库没有任何 Nexus 痕迹。 |
